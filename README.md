# TinyML Thermal Power Management — STM32F446RE

An academic mini-project implementing TinyML-based thermal power management on the STM32F446RE microcontroller, developed using STM32CubeMX and STM32CubeIDE.

## Overview
This project explores on-device machine learning (TinyML) techniques applied to thermal power management on an embedded ARM Cortex-M4 platform. It is being developed as part of a university course by a team of three.

## Hardware

- **MCU:** STM32F446RE (ARM Cortex-M4, 180 MHz)
- **Toolchain:** STM32CubeMX (peripheral/pin configuration), STM32CubeIDE (development & debugging)

## Repository Structure

```
├── Core/                          # Application source and headers (main.c, USER CODE sections)
├── Drivers/                       # HAL and CMSIS drivers (auto-generated by CubeMX)
├── TinyML_thermalManagement.ioc   # CubeMX configuration file — pin mux, clocks, peripherals
├── STM32F446RETX_FLASH.ld         # Linker script (Flash)
├── STM32F446RETX_RAM.ld           # Linker script (RAM)
├── .project / .cproject           # CubeIDE project metadata
└── .gitignore
```

## Getting Started

1. Clone the repository:
   ```
   git clone https://github.com/bat-daemon/TinyML_Thermal_power_mgmt_project.git
   ```
2. Open **STM32CubeIDE** → **File → Open Projects from File System** → select the cloned folder.
3. Build and flash to an STM32F446RE board (e.g. NUCLEO-F446RE) via ST-Link.

## Team

Is being developed by a team of 3 as part of an academic course project.

## Contribution Notes

- Only one team member should edit the `.ioc` file / regenerate CubeMX code at a time, to avoid merge conflicts in auto-generated code. Push immediately after regenerating so others can pull before making further changes.
- Application logic should be added within `USER CODE BEGIN` / `USER CODE END` blocks, which CubeMX preserves across code regeneration.
